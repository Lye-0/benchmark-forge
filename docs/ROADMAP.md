# 開発ロードマップ

一次仕様はIMPLEMENTATION_BRIEF.mdと追加のWINDOWS_IMPLEMENTATION_BRIEF.md。ユーザー指示により、フェーズの境界では確認を求めず、独立して実行できる実装・検証を続けます。ユーザーの判断や操作が必要になった場合は依存しない作業を完了してから停止します。

停止時は到達段階を全7段階（Phase 0〜6）の **N/7** で報告し、残る要件と必要な操作を併記します。現在の到達段階は **7/7（Phase 6）** で、全段階完了という意味ではありません。Phase 3〜6の実モデル・隔離・拡充・校正などの未完了要件は引き続き管理します。

## 実装済みの縦方向の経路

- 通常のPreview: 24生成器 / 15カテゴリ / 固定480件、freeze→複数モデル→採点→SSE→結果。
- 実行管理: 中断復元、再試行と全試行履歴、実プロセスクラッシュ、1000件処理。
- 私有holdout: Web/CLI→検証→private固定セット→既存スケジューラー。
- 速度: 固定テキストと要求出力の独立セット→測定→通常の能力と分離。
- ツール: native / agent→メモリ内の仮想在庫→スキーマ/禁止操作/最終状態→トレース。
- コード: 模擬モデルの生成コード→検証済みDocker→隠した入力で実行→ホスト側の正解と比較。
- 研究出力: 校正用観測、サンプル不足を隠さない80%維持補助指標、試行/メトリクス付きJSONL、gzip出力。

## 次の確認が必要な領域

1. Windows CI成功とWindowsでのOllama評価完了はユーザー報告で確認済み。CUDA/ドライバー/メモリの詳細とTransformers実推論は利用時に確認。Cloudで実モデル回答を代用しない。
2. Windows Docker DesktopのLinuxコンテナ、またはLinux/WSL2のDocker環境でsandbox-checkを通す。Linuxではrootless推奨。検証が通らない場合は無効のまま、環境差を調査する。
3. Codex liveは公式preview参加・認証・ツール禁止・正解/秘密の読取隔離が成立した後に検証。Pythonコード隔離と混同しない。

## 長期の研究・拡張

- 一般知識の正確な参照資料と利用条件、50〜80/100以上の独立生成構造。数合わせをしない。
- 実モデルの観測を使った校正、項目反応分析、意味的構造重複、十分な非公開holdout。
- 正式Standardは16分野の品質・固定銀行・層化配分を満たしてから発行する。現在はPreviewのまま。
- 同一tokenizer条件での固定トークン長の速度試験、内部token単位のTTFT、使用率/電力計測、巨大artifactの分割と確定セット自体のメモリ削減、数日規模の負荷試験。
- コードライセンスはユーザーが選択するまで設定しない。

Ollamaの可視テキストchunkによる初回受信計測、CPU/GPU構成の任意取得、全問題/結果/試行のスナップショット逐次アーカイブを追加済み。実機性能の検証とは区別します。

Windows共通基盤・PowerShell・CUDA extra・Docker状態診断・Windows/Linux CIを追加。Windows CI成功とOllama評価完了のユーザー報告を受領。GPU・Desktop・Transformersの確認は残る。Cloudでの型検査/依存解決とWindows実行は区別する。

無回答バッジのサイズを修正。出力上限による終了と無回答の関連を結果画面・ログ・Markdownで明示し、Markdownのモデル/推論条件・結果内訳を拡充済み。終了理由がない結果の原因は推定しない。

分割アーカイブ（JSONL/gzip）とマニフェストによる欠落・SHA-256検証を追加済み。確定セット自体のメモリ削減は引き続き未実装。結果画面に問題形式別・能力タグ別の成績と採点不可の絞り込みを追加済み。

`data.join`は回答JSONの構造を明記する1.1.0へ更新。公開固定20問のみ更新し、保存済みセットは旧版を保持。新旧セットの性能を直接比較しない。

Intel/NVIDIA併用Windows構成の検出と、任意のGPU全体単発計測（使用率・メモリ・電力・温度）を追加。連続サンプリング・モデル別Peakは未実装。RTX 5070 Laptop実機で構成・単発計測の取得成功をユーザー報告で確認済み。Windows/Linux CIの進捗取得・Docker診断の不安定要因へ対処し、更新後のCI結果を確認する段階。

OOM実検証はDocker状態フラグからcgroupのOOMカウンター増加と子プロセス終了の照合へ変更。実機構成や制限を緩めず、Actionsでの再検証を行う。

前回修正のActions完了をユーザー報告で受領。回答処理時間の平均・安定時のみの残り時間推定、履歴の二重読取解消、revision更新時のみのSSE集計を追加済み。

Windows実機のDocker未導入状態を確認済み。通常評価を継続し、生成コード評価だけ無効にする。Docker Desktop導入・実隔離の検証は、その機能を利用する段階で行う。未導入診断のPowerShell表示を改善し、非ゼロ終了コードは維持。

Ollamaの開始/再開時のモデルmanifest digest・テンプレートハッシュと問題結果の対応を保存。区間間の変更は警告し、直接比較・校正出力を拒否。取得不能時も通常評価を継続。ローカル重みの明示的な直接ハッシュCLIも追加。実測校正と、ハッシュ対象が推論で使用されたことの検証は残作業。

Windows Actionsで直接ハッシュ取得2件が失敗したため、CPython 3.12のstat/fstat間のctimeの意味の違いによる誤検出を修正。同じAPIの読取前後ではctimeを含む変更検出を維持し、回帰試験を追加。CloudでPython210件・Web16件・E2E4件成功。修正後のWindows CI結果確認が必要で、モデル再実行や追加インストールは不要です。
