# 開発ロードマップ

ユーザーの一次仕様はIMPLEMENTATION_BRIEF.md。実装済みと未検証の状態はSTATUS.mdに記録します。すべてを完成したと扱わず、動く垂直経路を維持して次のタスクへ進めます。

| Phase | 現在 | 後続の受け入れ条件 |
|---|---|---|
| 0 調査・基盤 | 完了（Cloud CPU） | GitHub Actionsの実行を別途確認 |
| 1 生成→採点→保存→CLI | 完了 | 版変更時のコーパス・セット互換性を保持 |
| 2 Web設定・実行・分析 | 完了 | 必要に応じアクセシビリティと大規模表示を拡充 |
| 3 実モデル・計測 | 一部 | Transformers専用ワーカー、Ollama実モデル、Codex安全transport/公式認証、GPU計測 |
| 4 長時間実行・隔離 | 一部 | 専用使い捨てワーカーと実侵入試験、in-flightのキャンセル、試行履歴、長時間負荷試験 |
| 5 生成器・ツール拡充 | 一部 | 品質を優先した20〜30構造、native/agentの仮想世界、対応検出と安全性の検証 |
| 6 研究品質 | 一部 | 私有holdout import、校正・厳密層化、環境収集・専用速度測定、WSL2/GPU検証 |

次の実装はPhase 3のTransformers用別プロセスワーカーと、ユーザーのローカルOllamaでの実推論確認から進めます。モデルロード・出力制限・timeout/cancel時のプロセス終了・局所メモリ計測を単独でテストし、API/CLIの既存契約へ接続します。

Codexの実接続は公式条件/認証の確認だけで有効にせず、公開問題だけが読める最小権限環境、不要ツールの禁止、採点器/秘密/正解へのアクセス不可を実証してから開始します。Cloudの開発用実回答はsub-agentのみとし、今後の新規sub-agentはユーザー指定の **gpt-6-astra / medium** を使います。

Standard正式版は別の独立目標です。16カテゴリの検証済みカバレッジ、十分な固定コーパス、全難易度域の共通分布、重みとorigin配分のテスト、汚染/非公開holdoutの設計を満たしてから版を発行します。少ない生成器の値違いを独立構造として水増ししません。
